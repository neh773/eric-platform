# Code of conduct

This project is a control system. People who run plants depend on the software behaving as documented. The conduct standard follows from that.

## Expected

- Discuss the software, the plant problem, and the change. Leave the person out of it.
- Say what you observed, on which version, with which logs. A log is more useful than a guess.
- Review for safety and for fit with the project goals. A clever change that writes to a field device without a test is not ready.
- Accept a "no" when a change is a non-goal. The goals file says what the project will not do.

## Not accepted

- Harassment, slurs, or personal attacks.
- Publishing another person's plant data, credentials, or private messages.
- Opening a pull request that hides a behavior change inside an unrelated edit.
- Demanding that a maintainer merge on a deadline.

## Reports

Email the maintainer at the address in SECURITY.md. Reports are read by the maintainer. A report that includes a plant's live credentials will have those credentials removed before anyone else sees it.
