# Container run recipes

Three ready recipes for the gateway image live in `packaging/compose`. Each builds the repository `Dockerfile`, listens on `OIP_PUBLISH_PORT` (default 8088) and seeds user `admin` from `OIP_ADMIN_PASSWORD` when the user source is empty. Do not commit a password. Doc source: FEATURES GAT-009.

| Recipe | State | Use it for |
| --- | --- | --- |
| `ephemeral.yaml` | tmpfs, gone when the container is removed | tests and demos that must start empty every time |
| `persistent.yaml` | named volume `gateway-data` | a gateway that survives container upgrades |
| `restore.yaml` | named volume, restored from a backup on first boot | a new or replacement gateway that starts from a known backup |

```sh
OIP_ADMIN_PASSWORD=... docker compose -f packaging/compose/persistent.yaml up -d
docker compose -f packaging/compose/persistent.yaml down      # container gone, volume kept
docker compose -f packaging/compose/persistent.yaml down -v   # volume deleted too
```

## Restore on first boot

Put a backup (made with the backup API or the admin Backups page) in a folder as `gateway.oipbk`. An encrypted backup also needs a file `passphrase` in that folder.

```sh
OIP_RESTORE_DIR=./restore docker compose -f packaging/compose/restore.yaml up -d
```

The gateway reads these variables:

- `OIP_RESTORE_FROM`: path of the backup file inside the container.
- `OIP_RESTORE_PASSPHRASE_FILE` (or `OIP_RESTORE_PASSPHRASE`): the passphrase of an encrypted backup. It is never logged.

Rules:

- The restore runs before any module starts, and only when the data directory holds no configuration (the built-in security and module defaults do not count) and no user other than the `admin` that `OIP_ADMIN_PASSWORD` seeds.
- After a restore, `restored-from-backup.json` on the volume records the file name and time. The same variable can stay set across restarts and never restores over live data.
- A set `OIP_RESTORE_FROM` that names a missing file, or an encrypted backup with no passphrase, stops the start with a message. The gateway never comes up empty while looking restored.
- The backup's users replace the seeded `admin`. Sign in with a user from the backup.
- A `gateway.yaml` inside the backup replaces the file on the volume and takes effect on the next start.

## Smoke check

`bash scripts/container_recipes_smoke.sh` builds the image, proves state survives recreating the persistent container, is absent from a recreated ephemeral one, and that a fresh volume restores a sealed backup taken from the first recipe. It uses throwaway passwords generated by the script. CI runs it after `scripts/image_smoke.sh`.
